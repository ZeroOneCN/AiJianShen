# 爱健身 · 迭代方案（1.9.6 → 2.0）

> 基线：1.9.5（`3835503`，分支 `test/upscaled-webp`）
> 依据：现有代码盘点 + Keep / Seven / Hevy / Strong / Fitbod 公开资料
> 日期：2026-11-19

---

## 一、先看清我们手里有什么

| 层 | 已有能力 | 成熟度 |
|---|---|---|
| 计划 | 目标 × 水平 × 频率 × 时长 × 器械 × 部位 → 生成 7 天课表（`Data.weekPlan`） | 够用 |
| 训练 | 计时驱动：预备倒计时 / 动作秒数 / 组间休息 / 暂停 / 跳过 / 换动作 / 收藏 / PR / 断点续练 | 能跑，但"掌控感"弱 |
| 内容 | 1324 个动作，每个带 `steps`（步骤）、`mistakes`（常见错误）、`breathingTip`、首帧图 | **很强，但没被用起来** |
| 记录 | session（分钟/动作数/kcal/feel）、体重、蓝牙秤体成分 | 够用 |
| 复看 | 热力图、周/月曲线、部位分布、报告 | 够用 |
| 坚持 | 连续天数、成就墙、挑战、模板、提醒 | 有，但"断了就回不来" |
| 数据 | 局域网同步、备份恢复（无账号、无云） | 差异化优势 |

一句话结论：**内容存量像一个专业教练，交互像一个秒表。**

## 二、竞品是怎么解的

| 竞品 | 关键做法 | 可引用的数据 | 我们能抄的 |
|---|---|---|---|
| **Keep** | AI 教练「卡卡」按目标/水平/器械/伤病史生成并**动态调整**计划；动作精讲；K1–K5 难度分级；语音陪练 | 2025 年 DAU 次日留存 **41.7%**（+2.7pp）；**高频使用 AI 数据分析功能的用户次日留存 69%**；语音陪跑调用 2100 万次；AI 生成计划完练率已比肩人工 | ①「练完给一个明确下一步」比多做 100 节课更能留住人；②难度要分级，不能一套课表打天下 |
| **Seven** | 7 分钟门槛；**替代动作**（gentler alternatives）；免手持模式（手臂佩戴 + 语音/振动报数）；Novice → Intermediate → Athlete 等级晋升；「三条命」——跳过一天掉一颗心，连丢三次进度重置 | 3000 万+ 用户、60 万+ 评分 | ①门槛压到"几乎不需要决定"；②给"做不了"的人一条退路，而不是逼他跳过；③**不抄三条命**——惩罚性设计对"已经断了的人"是加速流失 |
| **Hevy / Strong** | 标记完成即**自动启动休息倒计时**；每个动作可设不同休息；休息中 ±15 秒；RPE/RIR 强度自评；1RM 与容量曲线；渐进超负荷提醒 | 免费版就给自动计时 + RPE；3 个月内数据免费看 | ①"完成"这个动作必须由用户触发，才有掌控感；②强度要用一个极简的自我评分量化，才能谈渐进 |
| **Fitbod** | 按**肌肉恢复度**自动算下次重量与组次 | — | 徒手版对应物：按"上次这块肌肉练了多久/多久前"调整下次秒数与轮次 |

### 三条提炼

1. **留存的分水岭不在内容量，在"下次打开有没有明确的事可做"。** Keep 的 69% vs 41.7% 说的就是这件事——用户用了"分析/建议"类功能，留存立刻跳一个台阶。
2. **门槛越低越好。** Seven 把训练压到 7 分钟做到 3000 万用户；我们的最短时长还是 10 分钟，忙的时候直接放弃。
3. **徒手训练最缺"强度可量化"。** 器械派用重量×次数解决，我们只有秒数——秒数一样，做得快和做得慢强度差一倍。

## 三、差距诊断（按对留存的影响排序）

| # | 现象 | 用户心里的话 | 竞品对应 |

## 五、1.9.6 逐项设计

### 5.1 动作学习卡（把 `steps` / `mistakes` 用起来）

**现状**：日详情页点动作行走 `ReplaceSheet`（只换成另一个动作），没有"这个动作怎么做"的出口。

**方案**：点动作行 → 半屏卡，三段纵向滚动：

```
┌──────────────────────────┐
│  ▓▓ 动作首帧大图 ▓▓       │  16:9，圆角 18dp
│  深蹲                     │
│  腿臀 · 徒手 · 30 秒      │
├──────────────────────────┤
│  ① 双脚与肩同宽，脚尖略外 │  ← steps，按条编号
│  ② 屈髋下蹲，膝盖对脚尖   │     当前未选中时全部同色
│  ③ 蹲到大腿与地面平行     │
├──────────────────────────┤
│  ⚠ 常见错误               │  ← mistakes，暖灰底
│  · 膝盖内扣               │
│  · 塌腰                   │
├──────────────────────────┤
│  呼吸：下蹲吸气，站起呼气 │  ← breathingTip()
├──────────────────────────┤
│  [ 换成别的动作 ]  [ 开始 ]│
└──────────────────────────┘
```

**实现**：新增 `ExerciseSheet.java`（约 180 行），复用 `ReplaceSheet` 的弹层骨架与 `PhotoView`。入口挂在 `DayDetailActivity` 行点击，`ReplaceSheet` 的调用挪到卡片底部按钮。
**验收**：任意动作能打开；三段内容有空值时整块隐藏（不出现空标题）。

---

### 5.2 跟练分步高亮（这一条最影响"我做得对不对"）

**现状**：`tv_tip` 显示 `brief()` 一整段，计时走完就换动作。`WorkoutActivity.cueStep()` 是按"动作步（Step）"推进的，不是按要领分步。

**方案**：把要领拆成独立小行，**按时间均分高亮当前步**：

```
深蹲                          ← 第 2 轮 / 共 3 轮
────────────────
① 双脚与肩同宽，脚尖略外      ← 已过，INK_MUTED 45% 透明
② 屈髋下蹲，膝盖对脚尖        ← 当前，INK + 700 字重 + 左侧 3dp 主色竖条
③ 蹲到大腿与地面平行
────────────────
⏱ 18s
```

**实现要点**：
- `seconds / steps.size()` 得到每步时长；`elapsed % seconds` 落在第几段就高亮第几条。
- 步骤 ≤ 4 条时全部展示；> 4 条只展示当前 ± 1（避免挤掉进度环）。
- 单步时长 < 4 秒时不做高亮（闪得太快反而干扰），退回整段显示。
- 用 `SpannableString` + `BackgroundColorSpan` 或每步一个 `TextView` 都能做；**建议每步一个 TextView**，因为要加左侧竖条，Span 做不到。

**风险**：`tv_exercise`/`tv_tip` 区域高度会变，`activity_workout.xml` 的 weight 要重算（图区 62dp 已经让过一次，这次让 sheet 内部）。
**验收**：30 秒 3 步动作，每 10 秒高亮推进一格；暂停时高亮冻结。

---

### 5.3 结束页「下一步」建议卡

**现状**：`ResultActivity` 有 feel 三档（太轻松/刚刚好/太吃力），选完会调下周 level，但**用户看不到"具体改了什么"**。

**方案**：feeling 选完后，在下方生成一张建议卡，文案由规则引擎出：

| 条件 | 文案 |
|---|---|
| feel=太轻松 且 本周完成 ≥ 计划 | `下周三的深蹲从 30 秒加到 35 秒，轮次不变。` |
| feel=太轻松 但 本周完成 < 计划 | `先把出勤补上：本周还差 1 次，加时长反而容易断。` |
| feel=刚刚好 且有新 PR | `深蹲刷新纪录 32 秒。下周维持，把休息从 45 秒压到 40 秒。` |
| feel=太吃力 | `下周把这个动作降一档，秒数减 5 秒，先做稳。` |
| 连续 2 次以上太吃力 | `连着两次吃力了。下周三换成 10 分钟版，先把习惯接住。` |

- 卡片底部一个 `知道了`、一个 `改一下`（跳计划页）。
- 文案只用现有数据（session、feel、PR、weekDone），不引入新模型。

**实现**：新增 `Coach.java`（约 120 行，纯规则，无依赖），`ResultActivity` 插入一张卡。
**验收**：三档 feel 各自能出对应文案，不出现"分析了半天什么都没说"的空话。

---

### 5.4 操作条长按菜单

**现状**：操作条只有书签和换一个。想"这个动作今天不做了"只能点跳过（下一轮还会出现）。

**方案**：长按「换一个」展开两项：
- `本轮不再出现` —— `skipSet` 里过滤掉当前动作
- `以后别排这个` —— 写入 `Store` 的黑名单，`Data.weekPlan` 生成时过滤

**实现**：`PopupWindow` 复用 5.4 的下拉样式；`Store` 加 `K_BLOCKED`（Set<String>），`Data.withOverrides` 里过滤。
**风险**：黑名单过滤后某天动作数可能不足，需要兜底（不足 4 个时从同部位补）。
**验收**：屏蔽后当轮不再出现；重建计划也不再排它；可在设置里一键清空。

---

### 5.5 「做不了」→ 一键降级

**现状**：跳过后无记忆，下次照旧。

**方案**：跳过确认里加第三选项 —— `有点难，换个简单的`，按 `part + kind + gear` 找同部位、同类型、`seconds` 更短或 `gear` 更简单的动作，替换进当轮并记住偏好。

- 不新建"难度"字段：先用 `seconds` 和 `needsGear()` 做粗排；1.10 引入正式难度分级后再精确匹配。
- 替换后弹一条轻提示：`已换成「靠墙深蹲」，下次这个位置默认用它`，带 `改回来`。

**验收**：任意动作都能找到替代；找不到时不显示这个选项（不出现点了没反应的按钮）。

---

### 5.6 下拉补「退出本次训练」

**现状**：只能按返回键才弹确认框，藏在系统手势里。

**方案**：`⋯` 下拉最后加一条分隔线 + `退出本次训练`（红色文字），点开走同一个退出确认，并在确认框里说清「已练 6 分 20 秒会保存，下次可接着练」。

**验收**：三条功能项与一条危险项视觉分组；退出后首页出现"接着上次"入口。

## 六、1.10 逐项设计（机制层）

### 6.1 分部位能力等级（L1–L5）✅ 已落地（1.10.0）

原来 `level` 是全局三档，导致"上肢弱、下肢强"的人被平均。现在拆成 `胸背 / 腿臀 / 核心` 三条独立曲线：

- **自测**：`SelfTestActivity`，三个动作各选一个区间，点一下即定级，不弹键盘。
  - 俯卧撑 0–2 / 3–7 / 8–15 / 16–25 / 26+ → L1–L5
  - 深蹲 <10 / 10–19 / 20–34 / 35–49 / 50+ → L1–L5
  - 平板支撑 <20 / 20–39 / 40–74 / 75–119 / 120+ 秒 → L1–L5
- **映射**：腿臀/小腿 → 腿臀曲线；核心 → 核心曲线；胸背肩臂 → 胸背曲线；有氧取三者平均。肩臂不单独测。
- **秒数**：不再一天一个值，每个动作按自己的部位取 `15 + L×5` 秒（L1 20 · L2 25 · L3 30 · L4 35 · L5 40），放松日上浮 20 秒。
- **兼容**：老数据没有 `levels` 字段时按旧档位推导（新手 L2 / 进阶 L3 / 高手 L4），不会出现 0 级。
- **入口**：计划页第 02 步的「1 分钟自测」卡；训练设置「能力等级 · 分部位等级」。
- **反馈**：结束页「太吃力/太轻松」只调**当天主要部位**那一条曲线，其余不动。

### 6.1.1 动作难度推断（B2）

动作库没有难度字段，`Exercise.difficulty()` 按命名规律推断 1–5：`单臂/单腿/手枪/击掌/跳跃/倒立/杠铃…` +2，`下斜/负重/哑铃/史密斯…` +1，`靠墙/辅助/跪姿/半程…` −2，`上斜/坐姿/静态…` −1，拉伸 −1。不追求每个都准，只保证同部位内相对顺序可用。

`findEasier` 改为：目标难度 = min(用户该部位等级, 当前动作难度 − 1)，优先取难度最接近且不超等级的同部位动作；实在没有更简单的，才退回按秒数兜底。


### 6.2 周结算自适应 + 可撤销

每周日（或用户下次打开时）结算：完成率、平均 feel、跳过率。三项进规则，输出下周的 `days / minutes / level` 调整，并在首页顶部给一张「本周调了 2 处」的卡，点开看逐条原因，每条带 `改回来`。**必须可撤销**——自动化的信任来自"我能推翻它"。

### 6.3 断签救援 ✅ 已落地（1.10.0）

- `Store.streakInfo()` 返回 `{days, idle, absent}`，保留 **2 天宽限**（`Store.GRACE_DAYS`）：
  连着空 1–2 天不清零，超过才归零。今天是"还没到晚上"，不算缺席。
- 断了不显示 `0 天`：首页 chip 显示 `最长 12 天`，连续页大数字换成最长纪录，
  桌面小部件的单位改成「天最长」。
- 宽限期内的空档在首页日期条和连续页日历上用**浅灰点**标出，和「没练」区分开，
  连续页底部一句话说清「停一两天不清零」。
- 首页教练行在断签时改写成救援入口：`上次练到腿臀，今天 3 分钟就能接上，不算断。`
  点一下直接起 3 分钟训练（`Rescue.java`），优先取今天课表里的动作，不够 4 个补徒手。
- 提醒文案跟着状态走，不再是固定的"今天的动作已经排好"：

| 状态 | 标题 | 正文 |
|---|---|---|
| 从没练过 / 正常 | 该练一会儿了 | 今天的动作已经排好，花十几分钟动起来。 |
| 今天已练 | 今天已经练过了 | 不用再补，明天这一步接着来。 |
| 宽限内 | 接得上，别算了 | 上次练到腿臀。今天 3 分钟就算数。 |
| 超过宽限 | 不用从头算 | 上次练到腿臀。今天动 3 分钟就回来了。 |

### 6.4 3 分钟版 ✅ 已落地（1.10.0）

`MINUTE_OPTIONS` 加 `3 分钟`（`MINUTE_VALUES` 首位），定位不是"训练"，是"别断"。

- 不需要为 3 分钟单独写分支：`slots()` 算出来是 3–4 个动作 × 1 轮 × 30–50 秒，
  加休息正好 3 分钟出头（`rounds()` 自然落到 1，`perRound()` 落到 3–4）。
- 入口有三处：计划页时长滑轨、首页断签教练行、连续页「3 分钟接上」按钮。
  后两处走同一个 `Rescue.start()`，标题叫「3 分钟接上」。


### 6.5 收藏 → 一键成模板

动作库/训练页收藏页顶部加 `用收藏练一次`，把收藏的动作按部位排序灌进 `TemplatesActivity` 的新建流程，用户只需定轮次。

## 七、2.0 方向（差异化）

| 项 | 说明 | 为什么不现在做 |
|---|---|---|
| **语音陪练** | 现在是机械口令（"休息"/动作名）。改成四段人话：开始 / 过半 / 最后一组 / 结束，本地文案库 + 系统 TTS，不联网 | 依赖 1.9.6 的分步高亮，否则语音和画面对不上 |
| **强度自评（RPE 简版）** | 每轮结束问一句"还能再来几个"：0 / 1–3 / 4+，映射到下次秒数 | 需要先有 6.2 的自适应框架 |
| **周报一句话点评** | 本地规则引擎，如"这周三次都在 22 点后，恢复会打折，试试挪到 19 点" | 需要 ≥ 4 周数据才有说服力 |
| **家庭模式** | 一台设备多档用户，各自计划与记录 | 要改 `Store` 全部 key 的命名空间，成本高但**竞品做不到**（他们都绑账号） |
| **训练卡导出** | 把一次训练导出成图片/PDF，方便自己留存 | 优先级最低，分享功能刚被砍 |

## 八、明确不做

| 不做 | 理由 |
|---|---|
| 社区 / 排行榜 / 好友 PK | 要账号、要审核、要运营；且与"纯本地"定位直接冲突 |
| 云同步 / 微信登录 | 局域网同步已够用，上云就失去最大卖点 |
| 云端 AI 教练 | 需联网、需成本、需合规；本地方案（规则引擎 + 文案库）能拿到 80% 的体验 |
| 饮食 / 热量库 | 数据维护是无底洞，且与"训练 App"心智不符 |
| 课程视频 / 电商 | 版权与供应链，不是这个体量该碰的 |
| 三条命式惩罚 | Seven 有效，但那是"游戏化拉新"逻辑；我们的用户是"想坚持但坚持不了"，惩罚只会加速流失 |

---

## 九、怎么衡量（纯本地也能量化）

不接第三方统计，全部记在本机 `SharedPreferences`，报告页底部加一个隐藏入口（连点版本号 5 次）打开「使用诊断」：

| 指标 | 定义 | 采集点 |
|---|---|---|
| 完练率 | `complete()` 次数 ÷ 进入训练页次数 | `WorkoutActivity.onCreate` / `complete()` |
| 中途放弃率 | 退出且未完成 ÷ 进入 | `savePendingIfNeeded` |
| 跳过率 | 跳过次数 ÷ 动作步数 | `onSkip()` |
| 卡片打开率 | 动作学习卡打开数 ÷ 详情页动作行点击数 | `ExerciseSheet` |
| 建议采纳率 | 结束页点了 `改一下` ÷ 建议卡曝光 | `Coach` |
| 次周回访 | 本周练过的人下周是否再练 | `Store.sessions` 按周聚合 |

指标只做"自己看"，不上报。
